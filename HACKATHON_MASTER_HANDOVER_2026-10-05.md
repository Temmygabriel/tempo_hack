# 8. USAGEBAR — SIMPLE EXPLANATION

UsageBar is like opening a tab when renting something.

Example:
You rent a camera.

Instead of repeatedly paying:
- open a tab;
- set a maximum spending limit;
- use the camera;
- usage accumulates;
- close the tab;
- pay only what you actually used;
- unused amount remains/recoverable according to the payment-channel protocol.

Example:
- max = 50.00 test units
- actual usage = 12.40
- unused = 37.60

These are DEVNET/TEST amounts, not real Mainnet money.

One-line:
Pay for what you actually use.

# 11. USAGEBAR PRODUCT STATE MACHINE

READY
→ OPENING
→ FUNDED
→ ACTIVE
→ FINALIZING
→ SETTLED

READY:
No active channel/session.

OPENING:
Wallet authorization/channel-open process is happening.
No success claim until the actual transaction is verified.

FUNDED:
A real Payment Channel exists and has been read back from chain.

ACTIVE:
Service is running and usage can progress.

FINALIZING:
Final usage/settlement is being processed.
Do not fake progress.

SETTLED:
Final protocol state has been read back and the financial outcome is verified.

Product state is a human-friendly abstraction.
Actual Solana/Payment Channel state remains the source of truth.
